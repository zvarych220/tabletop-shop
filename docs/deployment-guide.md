# Посібник із встановлення та розгортання (Deployment Guide)

Цей документ містить покрокову інструкцію з розгортання та запуску повнофункціонального вебзастосунку **«Dice & Deck»** у локальному середовищі (XAMPP / LAMP / WAMP) та на віддаленому хостингу.

---

## 1. Системні вимоги

- **Операційна система:** macOS, Linux або Windows;
- **Веб-сервер:** Apache 2.4+ із увімкненим модулем `mod_rewrite`;
- **PHP:** версія 8.1 або новіша (з розширеннями `pdo_mysql`, `curl`, `json`, `mbstring`, `fileinfo`);
- **СУБД:** MySQL 8.0+ або MariaDB 10.4+;
- **Node.js:** версія 18.x або новіша (рекомендовано 20+ LTS);
- **Менеджер пакетів:** `npm` (версії 9+) або `yarn` / `pnpm`.

---

## 2. Покроковий процес розгортання

### Крок 1. Розміщення проєкту
Розмістіть директорію проєкту в кореневій папці веб-сервера:
- Для XAMPP на macOS: `/Applications/XAMPP/xamppfiles/htdocs/tabletop-shop`
- Для XAMPP на Windows: `C:\xampp\htdocs\tabletop-shop`
- Для Apache на Linux: `/var/www/html/tabletop-shop`

```bash
cd /Applications/XAMPP/xamppfiles/htdocs/tabletop-shop
```

---

### Крок 2. Запуск модулів XAMPP
1. Запустіть програму **XAMPP Control Panel**.
2. Увімкніть модулі:
   - ✅ **Apache Web Server** (порт 80 або 8080);
   - ✅ **MySQL Database** (порт 3306).

---

### Крок 3. Автоматична ініціалізація бази даних
У проєкті реалізовано інтерактивний скрипт міграції та сидингу, який:
- автоматично створює базу даних `tabletop_shop`;
- розгортає структуру з 8 таблиць (`schema.sql`);
- наповнює базу стартовими товарами, тестовими користувачами та замовленнями (`seed.sql`).

Відкрийте у браузері адресу:
```
http://localhost/tabletop-shop/backend/setup.php
```

Після виконання ви побачите зелену панель успішного розгортання з кількістю створених сутностей.

---

### Крок 4. Перевірка працездатності API
Перейдіть за адресою:
```
http://localhost/tabletop-shop/backend/public/api
```

Сервер повинен повернути статус успіху:
```json
{
  "success": true,
  "data": {
    "message": "Dice & Deck API is running",
    "version": "1.0.0",
    "timestamp": "2026-11-05 15:30:00"
  }
}
```

---

### Крок 5. Встановлення залежностей фронтенду
У терміналі в корені проєкту виконайте:
```bash
npm install
```

---

### Крок 6. Налаштування змінних оточення фронтенду
Перевірте або створіть файл `.env.local` у корені проєкту:

```properties
# Базова адреса API бекенду
VITE_API_BASE_URL=http://localhost/tabletop-shop/backend/public/api

# Джерело даних: 'api' (робота з бекендом) або 'mock' (офлайн-режим)
VITE_DATA_SOURCE=api
```

---

### Крок 7. Запуск клієнтського застосунку
Запустіть сервер розробки Vite:
```bash
npm run dev
```

У терміналі з'явиться посилання:
```
  VITE v6.x.x  ready in 240 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

Відкрийте **http://localhost:5173** у браузері.

---

## 3. Збірка для Production

Для формування оптимізованого продакшн-білда виконайте:
```bash
npm run build
```

Скомпільовані статичні файли (HTML, мініфікований JS з хешами та CSS) будуть збережені у папці `./dist`. Їх можна роздавати через будь-який веб-сервер або Nginx/Apache.

Для локального попереднього перегляду продакшн-білда:
```bash
npm run preview
```

## 5. Вирішення типових проблем (Troubleshooting)

### Помилка 404 при зверненні до API ендпоінтів (`/api/products` тощо)
- **Причина:** Веб-сервер Apache не підтримує URL Rewriting або вимкнено файл `.htaccess`.
- **Рішення:**
  1. Перевірте наявність файлу `backend/public/.htaccess`.
  2. У файлі `httpd.conf` Apache переконайтеся, що активовано модуль:
     ```apache
     LoadModule rewrite_module modules/mod_rewrite.so
     ```
  3. Для директорії сайту встановіть `AllowOverride All`.

### Помилка CORS (Cross-Origin Resource Sharing)
- **Причина:** Порт фронтенду (`5173`) відрізняється від порту бекенду (`80`).
- **Рішення:** Файл `backend/config/cors.php` вже налаштований на автоматичний дозвіл заголовків для `localhost:5173`. Якщо використовується інший домен, додайте його у список дозволених джерел у `backend/config/cors.php`.

### Помилка завантаження фотографій (Upload Failed)
- **Причина:** Відсутні права на запис у директорію завантажень.
- **Рішення:** Переконайтеся, що папка `backend/public/uploads` існує та має права на запис:
  ```bash
  chmod -R 777 backend/public/uploads
  ```
